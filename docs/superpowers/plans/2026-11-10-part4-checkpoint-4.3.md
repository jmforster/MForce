# Part 4, checkpoint 4.3: tables, Envelope and Curve — Implementation Plan

**Goal:** Part 4 section 8.1's third row, as decided with Matt on 2026-11-09: the Envelope's stage list and the Curve's knots stop being hand-read forms and become tables the nodes declare. One new kind lands, the enum column (`ArrayDescriptor::enum_labels`), so a table keeps its words on disk. `Envelope` declares eight stage columns in one group and `timeMode` as an enum setting, maps its output unconditionally (5.3), and reads its two accuracies once. `CurveNode` declares its knots as two columns, its expression rows as four, and `interp` and `mode` as enum settings. `tools/convert_patch.py` gains two rules that rewrite every stage list and every knot list in `patches/library`, `patches/baselines`, `patches/audition` and `patches/pending` column-major. Then the old forms stop being read: the loader's Curve branch goes, its Envelope branch reduces to the preset form's call, the editor's two stage-list functions and the four curve members of `GraphNode` go, and a file that still carries `stages`, `knots` or `exprKnots` fails to load, in the engine and in the editor, naming `tools/convert_patch.py`. No render in `patches/library` + `patches/baselines` moves.

**Architecture:** Part 4 sections 3.3, 4.3–4.4, 5.3, 5.7, 8.1–8.4 and 9.1 give the design; the survey behind this plan (2026-11-10: the loader's two branches, `envelope.h`, `curve_node.h`, the pin kinds, the editor's 74 curve references and its stage table, the converter, and a census of all 3,146 patch files, scripts in the planning session's scratch and reproduced in Task 0) adds the facts below, each of which a gate or a test then proves.

(1) **The census.** Files that hold a stage list or a knot list: library 23, baselines 9 (**32 in scope**), audition 373, pending 33, **438 in the four folders**; sweep 954, scratch 54, old 124. By form: a stage list in 29 in-scope files, 335 audition, 33 pending, as 8.1's row counts; a knot list in 15 in-scope files, 27 pending, and **291 audition files, where the row says 180** (4.2 turned audition's 457 paramMap curves into `CurveNode`s). Nodes: stage-form Envelopes 64 in scope (57 library, 7 baselines; 170 stages), 935 in the four folders (2,714 stages), 2,601 in the tree; preset-form 109 in scope, 2,078 in the tree; no Envelope anywhere has both `stages` and `preset`, and none has neither. `CurveNode`s 75 in scope, 1,364 in the four folders, 3,915 in the tree: `knots` on 74 / 1,359 / 3,594, `exprKnots` on 30 / 744 / 3,211.

(2) **What a stage object holds.** Five key sets in the tree. `holdPct`, the field removed on 2026-09-05, is still in 68 in-scope stages (3,160 tree-wide) and is 0 in every one. `nominal` is in no stage anywhere. `minSec` and `maxSec` are absent from 36 in-scope stages and `power` from 12, read today as 0. Every `type` is exactly `Linear`, `Expo`, `Sine` or `Hold` (`InverseExpo` appears nowhere, `Hold` nowhere in scope); every other value is a number; none is a negative zero. So the loader's silent fallbacks (an unknown `type` read as Linear, a stale `holdPct` ignored) are exercised by nothing but `holdPct` at 0.

(3) **Keys that were never read.** `release` and `releaseMax` on the `ar` Envelope of the six `algev_test_*` baselines (CLEANUP 24); `attack` on one stage-form audition node (`ks_piano_v6/pb_exc_B2_sep.json`, `env3`). One audition node says `"timeMode": "percent"` (`oboe_nasal1/flute_sibling.json`, `Ping_env`), read today as fraction because it is not `seconds`. Found and left for 4.5: 62 audition and 25 sweep Envelopes carry `"dynamicPins": null` *inside* `params`, which nothing reads (the allowlist admits the word).

(4) **`timeMode` becomes a setting on every Envelope, where today only two readers know it**: the stage half of the loader's branch and the `adsr` preset. On disk only `adsr` presets carry it among preset forms (76 audition, none in scope), so no file changes meaning; a non-`adsr` preset with `timeMode` would, and the converter drops the key there as never read.

(5) **`sustainLevel` and the order of a load.** The setting is a view of a four-slot stage list and, set by name, rewrites the four slots. Today a stage-form load builds the stages and then applies a `sustainLevel` key; with the stages as arrays the generic pass applies settings first and arrays after, in both hosts, so the key is applied before the table exists and the table stands. 30 stage-form nodes carry the key (1 library, 28 audition, 1 pending): 23 on a four-slot shape, each equal to its slots in float; 7 on another shape, where it does nothing. None differs, so no render depends on the order. The editor never writes the key on an Envelope. `viola_default` is the in-scope patch that pushes `sustainLevel` per note into a stage-form Envelope, so the null gate hears the rewrite on a table.

(6) **Curves.** Four shapes of node in the tree: knots with no `mode` (45 in scope), `mode: points` with knots and an empty `exprKnots` (20), `mode: expressions` with empty knots and expression rows (9), and the same with no `knots` key (1). Every knot is `[number, number]`, ascending in x, no x twice, 0 to 92 rows; every expression row has exactly `x`, `form`, `a`, `b`, the form `linear` or `power`; `interp` is `linear`, `logx`, `loglog` or absent (1 in scope). `oboe1` is among the expression-mode files.

(7) **The other tables are already whole.** Every `ExplicitPartials` (91 in the tree), `FormantPeaks` (78) and `LayeredRedNoiseSource` (3) node carries all of its group's columns at one length. So the ragged-table refusal can be the loader's own rule over every group now, and the `FormantPeaks` configurator, which is that rule for one type, has nothing left to do.

(8) **The files as text.** Of the 438, 424 are laid out exactly as `json.dumps(indent=…)` writes and 14 are re-laid one value per line (2 library, 3 baselines, 9 pending); 181 have CRLF endings and no final newline (5 in scope); two baselines hold a non-ASCII character (`perform/wiring_setting.json`, `perform/wiring_smoke.json`), which the driver today would rewrite as an escape; none holds a `\u` escape.

(9) **Who else touches a stage or a knot.** In the engine: `make_glide` (`instrument.h:456`), `compile_pitch_curve` (`pitch_bend.h:25`), the six factories and `envelope_json.h`'s `shape()`, all through `add_stage` and `stage(i)`. In the editor: the stage table pokes `env->stage(i)` in place with no lock, the curve editor assigns `cn->knots` on the live node with no lock, and the generic array cache (`GraphNode::arrayValues`) is the editor's copy, pushed through `set_array`.

(10) **What the gates cover.** The null gate's manifest and the A/B over the 131 render all 32 converted files; the comp gate renders `oboe1` and `piano_default`. Not in scope at all: a `Hold` or `InverseExpo` stage, a `timeScale` pushed per note into a stage list, `minValue` or `maxValue` fed by a signal, an `adsr` preset in seconds, an Envelope with no stages, and the `"percent"` oddity. A synthetic set renders each, in the old form under the base CLI and converted under every later build.
