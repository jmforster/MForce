# Part 4, checkpoint 4.2: the paramMap goes — Implementation Plan

**Goal:** Part 4 section 8.1's second row, as decided with Matt on 2026-11-09: `instrument.paramMap` stops existing as a form. One converter, `tools/convert_patch.py`, is born with the three existing converters as its first rules; it rewrites every paramMap in `patches/library`, `patches/baselines`, `patches/audition` and `patches/pending` as graph wiring (a `PerformNode`, and where the entry had a curve, a `CurveNode` and a `CombinedSource`). Then the three implementations of the paramMap are deleted: the engine's load-time conversion (`build_bindings`, `attach_perform_source`) with everything that existed only for it (the non-setting half of `PushBinding`, the Multiplex clone fan-out, `VoiceGraph::topMultiplex`, `ensure_constant`); the editor's (`convert_parammap_to_wiring`, the `s_loadedParamMap` stash, the Mappings dialog's legacy table and Add row, the conversion pair's paramMap stash); and the Python tool with its null gate. A file that still carries a paramMap fails to load, in the engine and in the editor, naming `tools/convert_patch.py`. No render in `patches/library` + `patches/baselines` moves.

**Architecture:** Part 4 sections 4.8, 5.5, 7.5, 8.1–8.4 and 9.1 give the design; the survey behind this plan (2026-11-09, scripts under the planning session's scratch, reproduced in Task 0) adds the facts below, each of which a gate or a test then proves.

(1) **The census.** 528 files carry a paramMap, 1,345 entries: library 67 files / 70 entries, baselines 15 / 15, audition 111 / 618, pending 9 / 11, sweep 103 / 357, old 223 / 274. The only name anywhere is `frequency`. **In scope (82 files, 85 entries) every entry is a bare `"node.pin"` string on a pin, none on a setting**: `AdditiveSource.frequency` 60, `FMSource.frequency` 11, `WavetableSource.frequency` 8, `SineSource.frequency` 3, `SawSource` 1, `TriangleSource` 1, `VarSource.val` 1 (`MPXTest3`, the one Multiplex voice in scope). So the in-scope conversion adds one `__perf_freq` `PerformNode` per file and turns each target pin into `{"ref": "__perf_freq"}`; no `dynamicPins`, no curve nodes. Audition is where the other forms live: 161 bare, 261 with a `curve`, 128 `curve` with `interp: loglog`, 54 `curve` + `vcurve`, 14 of those `loglog`; 333 targets on pins and 285 on settings (which become `dynamicPins`). Its setting targets are all curve-fed and all of two types — `KSString` (`t60` 111, `brightness` 53, `dispersion` 45, `inharmGain` 45, `detune` 18) and `Envelope.timeScale` (13, one with a `vcurve`); its pin targets are `KSString.frequency` and `HammerBank.frequency` bare, and curves into `SVFSource.cutoffFreq`, `BWLowpassFilter.cutoffFreq` and `CombinedSource.source2` (an Input pin as a target). Pending: 11 bare, all pins. In the four folders no file has a paramMap beside wiring, no target is already wired, structural, or missing; the only entries the converter cannot place are in `old/` (30 targets on `Formant` and `KSPianoString`, types the first rule rewrites or refuses first).

(2) **The engine already wires a paramMap.** `build_bindings` turns a pin target into the pin wired once to a chain rooted at the voice's frequency adapter (`patch_loader.cpp:1023–1031`), which is exactly what a file `{"ref"}` to a `PerformNode` builds; the wiring null gate has rendered that equivalence over the manifest since P2a. Two cases push instead of wiring: a setting target (`1038–1053`), which `dynamicPins` already expresses with the same binding (`bind_wiring`, `1198–1205`); and every entry on a Multiplex voice (`1013–1021`), pushed into each clone through `set_clone_param`. Converted, the Multiplex's `PerformNode` sits inside the template and each clone's copy reads the voice's adapter. **The one departure by construction** (8.1): a Multiplex voice under a bend or a glide — the push held the note-on frequency, the wire follows it. `MPXTest3`'s score has neither; a departure patch measures it (Task 0).

(3) **What the gates cover of the conversion, and what they do not.** The null gate's manifest holds 28 of the 82 (the wiring gate prints "28 carried a paramMap"); the close A/B covers all 82; but **8 of the 82 have no score and render silence** (`bell_fast_decay`, `bell_sweep`, `inst_spacy`, `ep_belly`, `ep_bright`, `ep_dark`, `ep_std`, `kick_studio_dry` — 4.1's finding), so their conversion is proved only by the score-less set, rendered with a score appended. And **no in-scope file has a curve, a vcurve or a setting target**: the 457 curves and 285 setting targets of audition are converted by rules whose last rendered proof was the 196-file gate of 2026-08. A synthetic set (Task 0) renders every form — in paramMap form under the base CLI, converted under each later build — before the engine code that defines the old meaning is deleted.

(4) **The converter's forms on disk.** Of the 202 files to rewrite, 142 are indented by two spaces and 60 by one; 14 (8 library, 3 baselines, 3 audition) have CRLF endings and no final newline; none holds a non-ASCII byte; 180 are already laid out exactly as `json.dumps(indent=…)` writes, so their diff is the new node, the changed pins and the deleted map, and 22 (9 library, 6 baselines, 3 audition, 4 pending) are re-laid one value per line. The driver is 3.9's (`migrate_deleted_types.py`'s `rewrite_file`): the file's own indent step, LF, a final newline, key order kept, a file with nothing to rewrite not written.

(5) **The editor's paramMap is 43 lines of reference over about 700 lines of code**, most of it already dead: `convert_parammap_to_wiring` (`main.cpp:1282–1420`) converts at load whatever it can, and since 3.9 the stash it leaves holds only a non-`frequency` name, an entry with no target, or a target naming no node — none of which exists in the tree. `apply_param_map` (`4306`) has no caller. (6) **`ensure_constant` has exactly the callers 9.3 says**: `build_bindings` (`patch_loader.cpp:998`) and the Multiplex's two private helpers (`multiplex_source.h:158–159`, `168–171`). `PushBinding::cs`, `cloneSlot` and `targetNodeId` are read only by the non-setting branch of `apply_note_bindings` (`instrument.h:409–413`), the re-push loop of `deliver_continuation` (`551–558`) and the slot registration in `prepare` (`222–223`).
