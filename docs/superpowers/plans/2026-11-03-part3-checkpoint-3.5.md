# Part 3, checkpoint 3.5: the envelope presets become one type; the `KSPianoString` alias goes — Implementation Plan

**Goal:** The six envelope preset classes (`AREnvelope`, `ASEnvelope`, `ASREnvelope`, `ADSEnvelope`, `ADREnvelope`, `ADSREnvelope`) are deleted; their six stage layouts become six `Envelope` factories, and the loader's preset form — today `"preset": "ar" | "adsr"` on an `Envelope` node — gains the other four names and the per-stage curve and power keys the classes carried, so that every node that named a preset class on disk is rewritten as an `Envelope` with the matching `preset`; `KSPianoString` is deleted as a registered name and every node that used it is rewritten as `KSString`; no render in `patches/library` + `patches/baselines` moves.

**Architecture:** Part 3 section 6 says `Envelope` "already builds its stages from a `preset` setting". It does not: `Envelope` has no `preset` setting. The preset is a *load-time form* — `envelope_from_preset_json` (`envelope_json.h`, the one dispatch both loaders share) reads `"preset"` and the knob keys and returns a plain `Envelope` whose stage list is the truth; the 1,125 nodes Part 3 counted as using it that way do exactly that (935 in the stages form, 167 `adsr`, 23 `ar`). The six classes are the other way round: `Setting<float> attack` and friends as members, and a `rebuild()` that lays the stages out again on every setting change. This plan collapses in the direction the code already leans and Matt's own note in `envelope.h` states ("presets are UI conveniences"): **the stage list is the one truth of an `Envelope`; a preset is a way of writing one.** Concretely: four static factories join `make_ar`, `make_adsr` and `make_adsr_abs` on `Envelope` — `make_as(attack, level, reverse)`, `make_asr(attack, level, release)`, `make_ads(attack, decay, level)`, `make_adr(attack, decay, decayLevel)` — each producing the float-for-float stage list the class's `rebuild()` produced; `envelope_json.h` becomes a table of six preset builders (`kEnvelopePresets`: name, builder) over those factories, each builder reading the class's keys with the class's defaults and applying the per-stage `*Curve`/`*Power` overrides the class applied, plus `envelope_preset_keys()`, the one list of keys the form reads, which the loader's allowlist test and the editor's key filter consult. The on-disk rewrite — `{"type": "ASEnvelope", "params": {...}}` → `{"type": "Envelope", "params": {"preset": "as", ...same keys...}}` — is the same rewrite the alternative design (the preset and its knobs as `Setting`s on `Envelope`) would need, so if Matt wants the knobs back in the editor that is an additive step on top of this one, never a second migration (ruling 1). `KSPianoString` is one registration line and one test line removed and one string rewritten on disk. Byte-identity is by construction: the factories write the same stage fields in the same order, the same class (`KSString`) is built by the same factory, and the null gate — whose manifest holds all eleven in-scope files this checkpoint rewrites — proves it across the rewrite; the A/B over the 132 against the pre-checkpoint binary and a synthetic set in the CLASS form (every knob off its default, the two forms with no user on disk) close the paths the scope lacks.

**Tech Stack:** C++20 (MSVC, CMake 3.20+, `/fp:precise`), the `engine_tests` harness (`CHECK`, `CHECK_NEAR`, `PinCounter`, `same_bits`, `load_instrument_patch_json`), Python 3.11 (`tools/tests` under ctest `tool_tests`), `python tools/gates.py`, `python tools/null_gate_perform_source.py`, `python tools/alloc_gate.py`, `python tools/ab_render_set.py`, `python tools/ab_render_time.py`, `python tools/test_stable_roundtrip.py`, `python tools/structure/check.py`, `python tools/lint_patches.py`.

## Review Focus

The nine places a byte or a behaviour could move that this plan claims do not, each pinned by the task named.

1. **The six layouts.** Each class's `rebuild()` is a pure function of its knobs (every call lays out from all current settings), so the stage list a class reaches after the loader has pushed its keys in descriptor order equals the layout from those keys at once. Task 1's equivalence test builds, for each of the six and a grid of knob values (defaults; every knob off its default; `reverse` both ways; curves 0..3; powers), the class through `set_setting` and the form through `envelope_from_preset_json`, and compares the eight stage fields per stage, the stage count, `absolute_time` and `has_adsr_shape_()` — while both exist. Task 3 deletes the class half; the form half stays as the layout tests with literal expected stages.
2. **The `adsr` form's defaults.** The existing form defaults `release` to 0.0 and `ADSREnvelope` to 0.1; `attack` 0.2, `decay` 0.1, `sustainLevel` 0.7 and the six clamps (`make_adsr`'s) agree; the curves (Linear, Linear, Sine; powers 0) agree. All nine `ADSREnvelope` nodes on disk carry `release`; the converter writes `release: 0.1` on one that does not (a unit test and the synthetic `adsr_class_bare` pin it). The `ar` form and `AREnvelope` agree on every default (`make_ar(0.2)`).
3. **Settings after construction.** On a class node the registry path applied `stage_accuracy`, `ramp_accuracy`, `timeScale` and `sustainLevel` through `set_setting` (a rebuild each); on the rewritten node the Envelope branch's `wire_params_generic` applies the same four through `set_setting` after the dispatch consumed `sustainLevel` for the level. On a two- or three-stage shape `set_setting("sustainLevel")` is a no-op (`has_adsr_shape_()` is false), on the four-slot shape it rewrites the four slots with the value the dispatch already wrote. Task 1's loader-level test loads a one-node patch both ways (class type and rewritten form) and compares stages and settings. No preset-class node in the active folders has a `dynamicPins` entry (Task 0's scan: 0 of 174); the tool refuses one that names a layout knob, since `attack` is no longer a setting.
4. **`seed`.** The registry path handed a `seed` param to the class factories (`if (seed) e->set_seed(*seed)`); the Envelope branch reads `seed` only in its stages block. Task 1 moves the read to cover both forms (ruling 6). A render depends on the seed only with `stage_accuracy` or `ramp_accuracy` below 1 — no Envelope in the active folders carries a `seed` key, no preset-class node carries a non-default accuracy, and Task 0 scans `MPXTest3`'s multiplex template (the one `MultiplexSource` in scope, whose perturbation injects `seed` into every template node). Pinned by a test, never by a render.
5. **Vibrato's two internal ramps.** `Vibrato::build_lfo` makes two `ASEnvelope`s and sets `attack`; Task 3 makes them with `make_as(attack.value)`: stage 0 `{0 → 1, Linear, 0}` at `attack` with clamps 0..1, stage 1 `{1 → 1, Linear, 0}` at 0 — the class's `rebuild()` with its defaults. The equivalence test's AS row at the Vibrato's defaults, the null gate's Vibrato patches (Task 0 counts them) and the A/B pin it.
6. **The alias.** `KSPianoString` and `KSString` register the same factory (`std::make_shared<KSString>()`, no seed); the rewrite changes one string per node; the null gate's four pianos (the only alias users in scope) and the A/B pin it.
7. **The derived label.** `source_registry.cpp` strips the suffixes `Source`, `Filter`, `Node`, `Envelope`; after Task 3 no registered name ends in `Envelope` but `Envelope` itself, whose label is pinned unchanged ("Envelope"); the suffix goes (ruling 10). Every other label is pinned by `kFamilyTable`.
8. **The editor's save.** A rewritten node loads in the editor through the same dispatch and saves in the stages form, as every preset-form node already does; `envelope_stages_to_json` emits all eight fields. Task 5's whole-corpus roundtrip (render identity of the roundtripped file) over library and baselines pins it, with the one known diff (`FormantSequence1`, backlog 3p).
9. **The tests bite.** Each task's close mutates once: Task 1 swaps `make_asr`'s release ramp to Linear (the equivalence test fails on the ASR row); Task 2 drops the converter's `release` default (its unit test fails); Task 3 leaves one registration line (`walked == 79` fails) and points the unknown-type message at nothing (the message test fails); Task 4 has no engine test (the editor is checked by the stamp and the roundtrip). Restored, ALL PASS. The Ledger records each flip and its failure line.
