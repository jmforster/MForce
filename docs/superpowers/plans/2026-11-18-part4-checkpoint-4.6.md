# Part 4, checkpoint 4.6: the module, beside the loader — Implementation Plan

**Goal:** Part 4 section 8.1's sixth row, as decided with Matt on 2026-11-09: the `patch` module is built beside the loader and proven as a second reader of the same files. `engine/include/mforce/patch/` holds the records (`Node`, `Graph`, `InstrumentBlock`, `Layout`, `Patch`, `Fragment`), the declarations table with slot acceptance, the codec (`patch_json`, with the Envelope's preset table moved in), `build_graph`, and `Patch::check()`. `render` gains `build_instrument(const Patch&)` and `build_sound(const Patch&)`. `mforce_cli --check` loads files through the codec and renders nothing. The row's first task comes first: the count of settings outside their declared range (0 in library and baselines), one declaration widened for the trombone family, the four clamp hooks of CLEANUP 19 deleted. **The twin gate** renders every file of `patches/library` + `patches/baselines` twice in one process, through today's loader and through `load_patch` and `build_sound` or `build_instrument`, and compares the two float for float, with the allocation count and the fault report. No host but the tests, `--check` and the twin gate calls the module: the command-line tool, the editor, `alloc_gate` and `test_figures` keep reading through the loader until 4.7. No file on disk changes and no render moves.

(2) **The out-of-range count, the row's first task.** Library and baselines: **0** settings outside their declared range. (3) **"The four clamp hooks" are four of seventeen.** CLEANUP 19's four are the wavetable evolutions `CellularAutomatonEvolution` (`rule` 0 to 255, `stepEvery` at least 1), `ReactionDiffusionEvolution` (`subSteps`), `HistogramEqualizeEvolution` (`bins`) and `SortErosionEvolution` (`swapsPerSample`): five int settings, each override nothing but the clamp. (4) **The preset form is most of the library.** 363 Envelopes are in preset form — in 60 library files and 42 baselines — and 935 in column form; none holds both forms or neither. // patch/node.h
```cpp
namespace mforce {

// One feed of a pin: the node it reads, and whether through a tap, which reads
// the value that node held at the end of the previous sample and so may close
// a loop.
struct Wire {
  std::string source;
  bool tap{false};
  bool operator==(const Wire&) const = default;
};

// One node of a graph as data: its id, its type, and what it holds for each
// name its type declares. A name sits in the map of its declaration's kind and
// in no other.
struct Node {
  std::string id;
  std::string type;
  std::optional<uint32_t> seed;                          // random at creation, stored for reproducibility
  std::map<std::string, float>              values;      // a pin's constant, while nothing feeds it
  std::map<std::string, std::vector<Wire>>  wires;       // a pin's feeds, in order: one, or several on a list or a multi slot; never empty
  std::map<std::string, float>              settings;    // a scalar setting as the engine stores it: a bool is 0 or 1, an enum its index
  std::map<std::string, std::string>        strings;     // a string setting
  std::map<std::string, std::vector<float>> arrays;      // an array, or one column of a table; a labelled column holds indices
  std::map<std::string, std::string>        dynamicPins; // a setting and the node that feeds it once per note
  std::string comment;
  bool operator==(const Node&) const = default;
};

} // namespace mforce
```

```cpp
// patch/type_declarations.h — what a registered type declares, read once from
// one instance of it into plain values.
struct TypeDeclarations {
  struct Param   { std::string name; float defaultValue{0}, min{0}, max{0}; std::string hint; };
  struct Input   { std::string name;
                   bool list{false};                     // several feeds in order: a list of signals, or a multi slot
                   bool slot{false};                     // takes a part, not a signal
                   std::string hint;                     // on a slot, what it takes, in words
                   std::vector<std::string> accepts; };  // on a slot, the registered types its door takes
  struct Setting { std::string name; SettingType type{SettingType::Float};
                   float defaultValue{0}, min{0}, max{0};
                   std::string defaultText;              // a string setting's default
                   std::vector<std::string> labels;      // an enum's labels, by index
                   bool structural{false}; };            // sizes or reshapes the node: takes no dynamic pin
  struct Array   { std::string name;
                   std::string group;                    // the table it is a column of; empty when it stands alone
                   float rowDefault{0}, min{0}, max{0};
                   std::vector<std::string> labels; };   // a labelled column's labels, by index

  std::string type;
  bool signal{false};                                    // a signal; false: a part
  std::vector<Param> params;                             // each list in declaration order
  std::vector<Input> inputs;
  std::vector<Setting> settings;
  std::vector<Array> arrays;

  const Param*   param(std::string_view name) const;     // null when the type declares no such name
  const Input*   input(std::string_view name) const;
  const Setting* setting(std::string_view name) const;
  const Array*   array(std::string_view name) const;
};
```

## The refusals

One format: **`<path>: <sentence>`**. The path is the place in the record, which is the place in the file: `graph.nodes[3].params.cutoff`, `instrument.release`, `layout.groups[0].members[2]`. A sentence about a node opens as the loader's do, `node '<id>' (<Type>): `, and where the loader has a sentence for the same refusal it is kept word for word (`unknown key`, a string on a pin, the feed's shape, the retired table's rows, both Envelope forms, the two dynamic-pin sentences, `does not accept a …`, the ragged table). `load_patch` puts the file's path in front.
