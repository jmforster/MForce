# Part 4, checkpoint 4.1: the seam's render half; `hiBoost` — Implementation Plan

**Goal:** Part 4 section 8.1's first row, as decided with Matt on 2026-11-09: today's built struct `Patch` is renamed `BuiltSound` and the live `StereoMixer` is renamed `Mixer`, which frees both names for the data model (2.2); the instrument voice loop, written twice in the loader, is written once behind both entry points; `perform_score_json` becomes `play_embedded_score` in a file of its own with the three `music` includes it needs, and the loader's two dead `music` includes go; the `mix` lookup — a second whole-graph build on every instrument-form load — is deleted; one mono adapter remains, made for a channel's source and the bare output and nothing else; `PitchedInstrument::hiBoost` is deleted with its two uses, the `--hiboost` flag and its six host sites; `mforce_cli --test-ornaments`, dead since 2026-08-10, is deleted. The two entry points keep their names until 4.7 (8.8 Q5). No patch file is touched. No render in `patches/library` + `patches/baselines` moves; every composition render moves (`hiBoost`), the one listening change of Part 4, decided 2026-10-05.

**Architecture:** Part 4 sections 5.8 and 5.9 give the shapes this checkpoint lands the render half of: `BuiltSound { sampleRate, frames, unique_ptr<Mixer> }` is what the standalone render builds; `play_embedded_score(PitchedInstrument&, const std::string& scoreText) → double` performs the block exactly as the loader does today and returns the score's end for the frame count, in `render`, until Part 5's play function replaces it (2.5: the block stays in the file; BACKLOG row 10); the plain-sound build wraps exactly the channel sources and the bare output in one adapter, where today `add_mono` wraps every signal node of every build and seven of the eleven branches skip it. What the survey adds, each a fact the gates then prove: (1) **the `hiBoost` deletion is byte-identical on the standalone render path by arithmetic**, because that path never set the field — the gain was `velocity * (1.0f + 0.0f) * volume`, and `1.0f + 0.0f` is exactly `1.0f`, `x * 1.0f` is exactly `x` for every finite `x`, and `/fp:precise` evaluates `(velocity * 1.0f) * volume` left to right without reassociating — so `velocity * volume` is the same float; the composition modes set `0.3f` at every site, and every one of their renders moves. (2) **The two mono adapters are one function twice**: `WaveSourceMono` and `ValueSourceMono` differ only in the pointer type they hold, `WaveSource` declares no `next()` of its own (`ValueSource::next()` at `dsp_value_source.h:102` is the one both call), so one adapter over `shared_ptr<ValueSource>` renders what either did, bit for bit. (3) **The `mix` lookup resolves to the mixer's own defaults on every file that has one**: the census over all 3,146 patch files finds seven instrument-form files with a node named `mix` (`ep_bright`, `ep_dark`, `ep_std` in the library; two in pending, two in old), none carrying `gainL` or `gainR`, so `resolve_param_or(mp, "gainL", 1.0f, …)` returned `make_shared<ConstantSource>(1.0f)` — exactly what `StereoMixer()`'s constructor installs; the throwaway build itself has no side effect a render can see (seeds come from the file or the branch's fixed fallback; the loader and the registry draw no global randomness; its stderr warnings are already suppressed by the voice builds' `warnedGates` set). (4) **The two voice loops are the same statements in the same order** but for the polyphony floor, `std::max(polyphony, minPolyphony)` with `minPolyphony` 0 on the render path, which is `polyphony` for every non-negative value and builds no voice either way below zero. (5) **The score moves as text** because 5.9's signature takes text and the module that will hold `Patch::score` never parses it (3.5); until then the loader passes `root.at("score").dump()`, and nlohmann writes a double with the shortest digits that read back to the same double and an integer as an integer, so each note's `get<float>()` is the float it was — a test asserts `json::parse(score.dump()) == score` over the 96 in-scope score-bearing files, and the null gate (42 of its 78 render through the score) and the A/B (96 of 132) are the rendered truth. The deletions the files prove dead: 2.5 §7's loader voice-loop pair (the meter's largest duplicate block, 62 lines at `patch_loader.cpp:1403–1464` and `1646–1691`, with the node-indexing pair beside it); `GraphResult::monoNodes`, `add_mono`, `WaveSourceMono`; the lookup at `1504–1521`; `pitch_bend.h` and `pitch_curve.h` at `patch_loader.cpp:17–18`, which nothing in the file uses; `hiBoost` at `instrument.h:207`, its uses at `429–432` and `634–637`, the flag at `mforce_cli/main.cpp:75–76`, the sites at `95`, `255`, `425`, `563`, `716`, `883` and `test_figures/main.cpp:1162`; `test_ornaments` at `mforce_cli/main.cpp:927–1043` with its dispatch at `1243–1244`, which loads `patches/PluckU.json`, removed by `eb964a1`.
