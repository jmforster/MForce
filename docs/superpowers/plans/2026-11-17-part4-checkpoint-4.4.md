# Part 4, checkpoint 4.4: every type a declaration — Implementation Plan

**Goal:** Part 4 section 8.1's fourth row, as decided with Matt on 2026-11-09: every node type says what it reads through its declared pins, and the loader stops knowing types by name. Three kinds land in `core`: the string setting (`SettingType::String`, a `StringSetting` pin), a node's own check (`Component::validate()`, with `warnings()` beside it), and — found in the survey, not in the row — the list of signal inputs (`InputList`), which `PhasedValueSource` needs and `MultiSource` has written by hand since 3.1. Then the nodes declare: `NameGate` its `name`; the three Butterworth filters `sections`; `HybridKSSource` its `targetPartials`; the Static pair their three settings each; `MultiSource` its `weights` and `delays`; `PhasedValueSource` its `sources`, a four-column table and `overlap`; `Partials` an `expandRule` slot; the Shaper its three refusals in `validate()`. Six loader branches go (`VarSource`, `RangeSource`, `SegmentSource`, `Vibrato`, the Butterworth trio, `HybridKSSource`), the `NameGate` branch shrinks to its vocabulary lookup, the Shaper and `expandRule` blocks of `wire_params_generic` go, and ten of the eleven configurators go (`FormantSequence`'s waits for the codec, as 8.1 says). `tools/convert_patch.py` gains five rules; 30 files in `patches/library`, `patches/baselines`, `patches/audition` and `patches/pending` are rewritten, six of them tracked. A file that still carries an old form fails to load, in the engine and in the editor, naming the converter. No render in `patches/library` + `patches/baselines` moves.

**Architecture:** Part 4 sections 3.2–3.3, 4.2–4.4, 5.4, 5.6, 5.7, 5.10, 8.1–8.6 and 9.1 give the design; the survey behind this plan (2026-11-17: the loader's eleven branches and two blocks, the eleven configurators, twenty node headers, the pin kinds and the wiring door, the editor's settings cache and its special cases, the converter, and a census of all 3,146 patch files — `renders/scratch/ab44/planning/census44.py`, reproduced in Task 0) adds the facts below, each of which a gate or a test then proves.

(1) **The census, by what changes on disk.** 30 files in the four folders: library 3 (`ep_bright`, `ep_dark`, `ep_std`: per-feed weights), baselines 3 (`filter_sweep_test`: `cutoff`; `repeating_segment_test`: `gap`; `phased_test`: the stage rows) — **six tracked** — audition 22 (8 hold `"operation": "add"`, 14 hold a `VarSource` with no `val`), pending 2 (`inst_fm_rhodes_clack`: weights; `inst_fm_rhodes_dual`: `add`). Not converted: sweep 4, scratch 10 (6 inline `expandRule`, 4 `cutoff`), old 67 (inline `expandRule`). 8.1's row counts are right for every form it names; the 14 `VarSource` files are the one thing it lacks.

(2) **The nodes, in scope / in the four folders / in the tree.** `VarSource` 5 / 19 / 34 (5.7 says 6 in scope); `RangeSource` 12 / 98 / 209; `SegmentSource` 8 / 386 / 514; `Vibrato` 11 / 302 / 707; Butterworth lowpass 11 / 67 / 190, bandpass 6 / 75 / 200, highpass 0 / 9 / 10; `SVFSource` 20 / 757 / 3,012; `HybridKSSource` 1 / 1 / 2; `MultiSource` 3 / 4 / 6; `PhasedValueSource` 1 / 1 / 1; `RepeatingSource` 1 / 2 / 2; `CombinedSource` 119 / 1,614 / 5,898; `Shaper` 9 / 213 / 1,374; `NameGate` 0 / 5 / 5; `CrossfadeSource` 0 / 0 / 1; `StaticVarSource`, `StaticRangeSource` and the `ExpandRule` node 0 anywhere.

(3) **Every default was read against its declaration, and one differs.** The `VarSource` branch reads an absent `val` as 0.0 and the pin declares 1.0. Fourteen audition files (`bwg_perc1`, `bwg_perc2`, seven each) hold `{"type": "VarSource", "params": {}}` as the silent input of six band filters: a default-constructed node would feed them 1.0. The converter writes `"val": 0.0` there (Ledger 8). Everything else agrees: `var`, `varPct` 0 and `absolute` true; `RangeSource` 0, 1, 0 and `normalized` false; `Vibrato`'s seven; `sections` 2; `RepeatingSource` 0.5, 0, 0.2, 0; `CombinedSource` `operation` 0 and `gainAdj` 0; `CrossfadeSource` 0.5, 0.1, 0; the three default seeds (`Vibrato`, `SegmentSource`, `HybridKSSource`) are the same number in the branch and in the factory. In the four folders every `Vibrato` carries all seven settings, every `SegmentSource` its `values` and a bool `oneShot`, every `RangeSource` its three pins.

(4) **What the configurators do that a declaration does not.** `RepeatingSource`'s writes all four members *after* the settings pass, from `duration`, `durVarPct`, `gap`, `gapVarPct`: a file's `gapDuration` is overwritten by `gap`'s default today. One pending file holds `gapDuration` without `gap`, at 0.2, the default, so nothing depends on it. `CombinedSource`'s maps the ordinals 0 to 3 to themselves, matches a string in any case with `add` as a second word for Mix, and throws on anything else; in the tree `operation` is never absent, the numbers are 0, 1 and 3, and the strings are `multiply`, `sum` and `add` (9 nodes). The two Butterworth configurators are dead code: the loader's branch takes the three types before the registry path is reached, and reads `cutoff` itself. `SVFSource`'s `cutoff` is on no node in the four folders (4 in scratch, each beside a `cutoffFreq` that the alias then overrides). A configurator's `p.value(key, default)` throws on a string where the settings pass skips it in silence; no float setting in the tree holds a string (the census lists every string in a `params` bag: enum labels, `preset`, `field`, `name`).

(5) **`MultiSource`.** Weights sit on every feed of four nodes (twelve weights; the three library files and one pending); no feed anywhere carries a `delay`; no feed of any other type carries a key beside `ref` or `tap`; no `source` is a single object. The three library files are score-less instruments, so the null gate, the A/B over the 131 and the roundtrip gate render them as silence: **the weights are heard by the score-less arm alone** (`ab43/scoreless_table/` holds `ep_bright`, `ep_dark`, `ep_std` with a score appended). (6) **`PhasedValueSource`.** One baseline, three rows, each with all five keys and a `{"ref"}` source; `overlap` 0.15. A stage is a source and four numbers, so the node needs the same list of signals `MultiSource` holds: written again by hand it would be the second copy.

(7) **`expandRule` is on no node in the four folders in either form**, the `ExpandRule` node type is in no file anywhere, and the ref form is in no file anywhere; the inline form is on 73 nodes of scratch and old. Today a ref whose target is missing or of the wrong kind is ignored in silence.

(8) **The Shaper.** Under hysteresis: 1 in scope, 109 in the four folders, 235 in the tree, and every one carries the `morph` key, so today's advisory prints for all of them; none has `morph` wired or non-zero and none lacks `values2`. (9) **The editor.** It drops per-feed weights at load (its second pass makes links from `ref` and reads nothing else), and no gate hears it (5). The settings cache is `vector<pair<SettingDescriptor, float>>` with 31 uses. `create_dsp` has five special cases, two of them `VarSource` and `RangeSource`. (10) **Who else is touched.** The constructors that lose their arguments have 28 callers in `engine_tests`, 2 in the editor and 2 in `vibrato.h` (its two private `RangeSource`s, built with `normalized` true). `setting_descriptors()` is read at three places in the loader (the unknown-key test, the settings pass, the dynamic-pin check), once in the command-line tool (`--dump-descriptors`, which the lint and the converter read), once in the editor and at 21 places in the tests. `PinKind` is switched on in `component.h` and `driven_part.h`. `Input`'s constructor carries a `multi` flag that five declarations pass as `false` and none as `true`. The lint's `MANUAL_KEYS` are `sections` and `oneShot`.

## Global Constraints

- **Byte-identity is total in scope**: the A/B over the 131 against `renders/scratch/ab43/old/hashes.txt` → 0 DIFFER; `python tools/null_gate_perform_source.py --jobs 3` → 77/77, the manifest's hashes never touched. No departure by construction is expected; a file that moves is a finding.
- **The score-less nine are a first-class arm** (Architecture 5): `renders/scratch/ab43/scoreless_table/` against `ab43/scoreless/old/hashes.txt` by file name, at Tasks 1, 2, 3 and 6 whole and at Task 5 for the three converted. So is the synthetic set.
- **The node change, the conversion and the deletion are proved separately.** After Task 3 the engine reads both forms and the tree is the base's. Task 5 converts the tree under Task 3's binary, not rebuilt. Task 6 deletes the old readers. A difference names its task.
- **Gates by task (rule 2).** *An engine task* (1, 2, 3, 6): build every target; `engine_tests` ALL PASS; the null gate; the 131; the nine; the synthetic set; `python tools/comp_template_null_gate.py render <stage>` and `compare post43 <stage>` → 21 SAME; `python tools/alloc_gate.py --jobs 3 patches/library patches/baselines` → 0; `python tools/test_stable_roundtrip.py patches/library patches/baselines --jobs 3` → 0 id changes, 0 new render diffs, the 6 known; `gates --fast` with the base's result (ctest, the stamp and the allocation gate PASS; the smoke at its standing `wiring RENDER DIFF`, so the tool prints FAILED). *Task 4*: the tool tests and `--check`. *Task 5*: named there. The coordinator: the binary's hash, the null gate, the diff.
- **Every commit builds every target, the UI included**: a node type is the engine's and the editor's at once, so each node task carries the editor's half. The meter's known answers for `main` and `draw_properties_panel` (`tools/structure/tests/test_structure.py:148–149`, 1,704 and 926 at the base) move with the editor's edits and are updated in the same commit.
- **The untracked folders (8.4)**: `patches/pending` is copied whole to `renders/scratch/ab44/pending_before/` before anything is rewritten; audition is rewritten in place; no gate time on either beyond `convert_patch.py --check`. Sweep, scratch and old are not converted.
- **Nothing is written to a tree root; nothing under `scores/` changes;** in `patches/` only the six tracked files and the two untracked folders change, and only by the converter.
- **The real-time rule**: nothing on a `next()` path allocates. The three derived layouts (`MultiSource`'s entries, the Phased stages, the hybrid's targets) are rebuilt at a wiring or an array change and never at a note.
- **No executor commits or stages.** Edits through script files that keep each file's line endings (CRLF and LF are mixed); one `cmake --build` at a time; a failed build's stale binary is not a pass; the reviewer reads code only at the commits while a mutation run edits the tree.
- **New code**: one rule per file under `tools/convert_rules/`; no date, backlog id, REVIEW, Part or checkpoint number in a code comment.
- **Dates:** `date` first; this plan is dated 2026-11-17.
