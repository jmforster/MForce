# MTD Figure Extraction Pipeline — Design Spec

**Date:** 2026-05-05
**Status:** Draft (Phase 1 — manual segmentation only)
**Predecessor:** PatternLibrary + LibraryPassageStrategy (`docs/superpowers/specs/2026-04-27-pattern-library-design.md`).
**Companion (deferred):** Auto-segmentation algorithm — separate spec, written after Phase 1 produces ground-truth data.

---

## Context

The Pattern Library landed on 2026-04-27. Auditioning real Patterns confirmed that the structural recipes (AAAB-style slot patterns, cadence markers, elision) are right but the slot *content* — generated by RFB — is too random/uniform to read as music. The "computer music" verdict.

Yesterday (2026-04-28) we identified the **Musical Theme Dataset** (MTD, AudioLabs Erlangen) as a license-friendly corpus of 1,638 themes from Barlow & Morgenstern, with rich metadata. Themes are figure / single-phrase scale, mostly antecedent-only when the original theme has a longer arc. Suitable as a source of real motifs to fill Pattern Library slots.

The plan is to extract three pools (PulseSequence-only, StepSequence-only, paired Figures) from MTD and add a `RealMotifSlotFiller` strategy that retrieves from those pools in place of RFB. Steps 1-5 of the build order get our ears on real-motif Pattern fills before we write any auto-segmentation algorithm; step 6 (the algorithm) becomes a separate spec when we have data.

This spec covers steps 3-5: the extraction pipeline + audition + slot-filler. Steps 1-2 (curation + hand-marking) are already tooled (see `corpus/mtd_seg/pick_curated.py`, `prep_groundtruth.py`, `parse_groundtruth.py`).

---

## Goal

Produce three flat, license-clean libraries of musical figures suitable for slot-fill in `LibraryPassageStrategy`. Each figure carries enough metadata for filtering by composer, era, polyphony, instrument, length, etc. The figure encoding matches existing mforce conventions (`step[0] = 0`, FC.leadStep bridges between figures).

Phase 1 deliverable:
- 20 curated MTD themes hand-segmented into figures.
- ~60–100 figures total (assuming 3–5 figures per theme).
- Three pools written to `corpus/mtd_seg/pools/`.
- `audition.py` for ear-checking individual figures.
- `RealMotifSlotFiller` strategy wired into `LibraryPassageStrategy` Phase 2.

---

## Pipeline

```
ground_truth/MTD####.txt        (Matt edits; inserts | between notes)
       │ parse_groundtruth.py
       ▼
ground_truth_json/MTD####.json  (boundary indices)
       │ extract.py
       ▼
figures/MTD####.json            (per-theme: PS + SS + chromatic sidecar)
       │ build_pools.py
       ▼
pools/{pulse,step,paired}.json  (flat libraries)
       │ RealMotifSlotFiller
       ▼
LibraryPassageStrategy slot fills
```

Each stage is restart-friendly. `extract.py` skips themes whose `figures/MTD####.json` already exists and whose source is older than the output. `build_pools.py` rebuilds from scratch (cheap).

## Per-theme JSON: `figures/MTD####.json`

```json
{
  "mtdid": "0389",
  "composer": "Bach",
  "work": "BWV0846-01",
  "work_title": "Prelude in C",
  "instrument": "Harpsichord",
  "polyphony": "Monophon",
  "key":      {"root_name": "C", "mode": "major", "sharps_flats": 0},
  "time_sig": [4, 4],
  "extraction_version": "1.0",
  "source": {
    "midi": "corpus/mtd_full/midi/MTD0389_score.mid",
    "html": "corpus/mtd_full/html/MTD0389.html"
  },
  "total_notes": 16,
  "num_figures": 4,
  "figures": [
    {
      "id": "MTD0389_f0",
      "source_index": 0,
      "num_notes": 4,
      "pulse":      [1.0, 0.5, 0.5, 1.0],
      "step":       [0,   +1,  +1,  +1],
      "chromatic":  [0,    0,   0,   0],
      "lead_step_from_prev": null,
      "first_note_midi":     60,
      "first_note_bar_beat": [1, 1.0],
      "total_beats": 3.0,
      "warnings":   []
    }
  ]
}
```

### Field semantics

| Field | Meaning |
|---|---|
| `pulse[k]` | Inter-onset interval (beats) from note `k` to note `k+1`. For the last note of a non-final figure, `pulse[k]` is the IOI to the *next figure's* first note (this absorbs any inter-figure silence into the prior figure's last pulse — acceptable for the curated rhythmically-regular Phase 1 set; may need revisiting if long inter-figure rests get common). For the last note of the *theme* (no next onset exists): fallback to played duration. Snapped to the quantization grid. |
| `step[k]` | Diatonic scale-degree delta from note `k-1` to note `k`. By mforce convention, `step[0] = 0` always; the figure's first note is positioned by phrase context, not by an internal step. |
| `chromatic[k]` | `0` = diatonic, `+1` = raised semitone (♯), `-1` = lowered semitone (♭). Applied at realize time *after* walking the diatonic step. |
| `lead_step_from_prev` | Diatonic-degree delta from the previous figure's last note to this figure's first note. `null` for `source_index = 0`. Optional bridging info; a strategy may use it to chain figures from the same source theme or ignore it. |
| `first_note_midi` | Original MIDI pitch of the figure's first note. Provenance only; not required for re-deployment. |
| `first_note_bar_beat` | `[bar_number, beat_in_bar]` of the figure's first note in the source theme. Provenance / debugging. |
| `total_beats` | `sum(pulse[0..n-1])`. The figure's full duration. |
| `warnings` | Strings naming any quantization or off-scale issues encountered during extraction. Empty `[]` for clean figures. |

### `step[k]` = 0 invariant

The first unit's `step` is always 0, matching the project's `step[0]=0` convention (`memory/arch_fc_and_step_zero.md`). Inter-figure transitions are described by `lead_step_from_prev` on this figure, *not* by `step[0]` of this figure.

## Pulse quantization grid

Each IOI is snapped to the nearest of:

| Class | Values (beats) |
|---|---|
| Plain | 4, 2, 1, 0.5, 0.25, 0.125 |
| Dotted | 3, 1.5, 0.75, 0.375 |
| Triplet | 2/3 ≈ 0.667, 1/3 ≈ 0.333, 1/6 ≈ 0.167 |

Tolerance ε = 0.05 beats. If the actual IOI is within ε of any grid value, snap silently. Otherwise snap to the nearest grid value and append a string like `"pulse[3] off-grid by 0.07 (raw 0.42)"` to the figure's `warnings`.

The 0.05 ε is generous enough to absorb articulation/timing slop in the MTD MIDIs but tight enough that genuinely odd durations get flagged.

## Chromatic encoding

**This section may be revisited.** The current design follows the legacy
passing-tone-on-Scale model: SS stays purely diatonic, chromatic alterations
ride along in a parallel sidecar. The alternative — promoting SS to carry per-step
semitone annotations directly (`U+`/`U-`) — is parked for now but on the table
if the sidecar approach turns out to fight us at slot-fill time.

### Algorithm

For each note in a figure:
1. Compute `pc = midi_pitch % 12`.
2. Compute `rel = (pc - tonic_pc) % 12`.
3. If `rel` is in the diatonic scale (major: `[0,2,4,5,7,9,11]`; natural minor: `[0,2,3,5,7,8,10]`): emit step relative to `prev_step` with `chromatic = 0`.
4. Else, raise-first heuristic:
   - If `(rel - 1) % 12` is in scale → emit step at the lowered diatonic neighbor's degree, `chromatic = +1` (raised).
   - Else if `(rel + 1) % 12` is in scale → emit step at the raised diatonic neighbor's degree, `chromatic = -1` (lowered).
5. Else (off by ≥ 2 semitones — extremely rare in pre-1910 themes filtered to be ≤ 20% chromatic): can't encode. Snap to nearest diatonic with `chromatic = 0` and add a warning.

Raise-first means C♯ in C major is encoded as "scale degree 1 (C), raised by 1" rather than "scale degree 2 (D), lowered by 1." Both are valid spellings; we pick raise-first for consistency.

### Realize-time

Walk SS to the diatonic note: `pitch_diatonic = step_into_scale(anchor, sum(step[0..k]))`. Then apply: `pitch_actual = pitch_diatonic + chromatic[k]` (in semitones). The legacy `Scale.getPassingTone()` mechanism is the natural place for this if/when it lives in the runtime.

## Pool format

Three flat JSON lists in `corpus/mtd_seg/pools/`. All entries share the `id` field across pools, so a strategy can join the three pools by id if it wants.

### `paired.json`

```json
[
  { "id": "MTD0389_f0",
    "pulse":     [1.0, 0.5, 0.5, 1.0],
    "step":      [0,   +1,  +1,  +1],
    "chromatic": [0,    0,   0,   0],
    "num_notes": 4,
    "total_beats": 3.0,
    "source": {
      "mtdid":      "0389",
      "composer":   "Bach",
      "work":       "BWV0846-01",
      "work_title": "Prelude in C",
      "key_mode":   "major",
      "instrument": "Harpsichord",
      "polyphony":  "Monophon"
    } }
]
```

### `pulse.json`

Same shape minus `step`/`chromatic`. Used by strategies that want only rhythmic shapes (e.g., RS-of-A applied to SS-of-B).

### `step.json`

Same shape minus `pulse`. Carries `step + chromatic + num_notes + source`.

The `source` block is inlined per-entry (denormalized) so a strategy can filter without joining tables. Rationale: pools will be small (~100–2000 entries Phase 1, ~5000–10000 Phase 2), filter latency dominates query patterns.

## `extract.py`

Reads:
- `corpus/mtd_full/midi/MTD####_score.mid` (or `_edm-corr.mid` if score missing)
- `corpus/mtd_seg/ground_truth_json/MTD####.json`
- `corpus/mtd_full/manifest.csv` (one row lookup)

Writes:
- `corpus/mtd_seg/figures/MTD####.json`

CLI:
```
python extract.py                 # extract all themes with ground_truth_json/ entries
python extract.py 5753 0389 ...   # specific MTDIDs
```

Behavior:
- For each theme: parse MIDI, parse manifest row, parse boundary list. Walk notes; segment into figures at boundary indices.
- For each figure: compute pulse (IOIs, last figure's last note duration), step (diatonic deltas with `step[0]=0`), chromatic (sidecar). Quantize, log warnings.
- Compute `lead_step_from_prev` from previous figure's last note's diatonic position to this figure's first note's diatonic position.

Errors (per Phase 1 scope):
- Boundary at index 0 or > total_notes → reject theme, print error.
- Figure with 0 notes (two adjacent boundaries) → reject theme, print error.
- Figure with > 8 notes → emit but warn (`"figure has 9 notes — likely a phrase, not a figure"`).
- Note off-scale by ≥ 2 semitones → emit nearest diatonic with `chromatic = 0`, warn.
- Missing keysig in MIDI → default `(sf=0, mi=0)` (C major), warn.

## `build_pools.py`

Scans `corpus/mtd_seg/figures/*.json`, aggregates into the three pool files. Idempotent. No CLI args (always rebuilds all three pools from current per-theme files).

---

## `audition.py`

Picks one pool entry by id (or random) and:
- Renders to a short `.mid` at `corpus/mtd_seg/auditions/<id>.mid`, OR
- Renders to a short `.wav` via `mforce_cli` using a default patch (caller-configurable).

CLI:
```
python audition.py MTD0389_f0           # render specific figure
python audition.py --random             # pick random from paired pool
python audition.py --composer Bach      # random Bach figure
python audition.py --instrument Piano   # random piano figure
```

Output paths configurable. Phase 1: writes `.mid` only (no DSP integration); user plays in any MIDI player.

---

## `RealMotifSlotFiller` (engine)

`engine/include/mforce/music/real_motif_slot_filler.h`. Lives alongside RFB inside `LibraryPassageStrategy`.

Loads `pools/paired.json` (or `pulse.json` + `step.json` for the unpaired modes) at construction. For each Pattern slot needing a motif of `totalBeats = T`:
1. Filter pool to entries with `total_beats == T` (or within ε for slop).
2. Apply optional source-metadata filter (composer / era / polyphony / instrument).
3. Random pick from the filtered set; emit as a `MelodicFigure` whose `units[0].step` is forced to 0, whose subsequent `units[k].step` come from the pool entry's `step[k]`, and whose durations come from the pool entry's `pulse[k]`.

Chromatic encoding at slot-fill time: emit a parallel `chromatic` annotation on the figure (using a sidecar field on the runtime Figure) OR resolve it at compose time by inserting passing tones via the active Scale's `getPassingTone` equivalent. Decision deferred — the sidecar may need to live on the runtime `MelodicFigure` if the legacy Scale-walking machinery isn't yet ported.

Phase 1 audition target: a Pattern fill where every slot is filled by `RealMotifSlotFiller` instead of RFB. If the result reads as more "musical" than RFB-filled, the pipeline is validated.

## Success criteria

1. `extract.py` against the 20 curated themes (after Matt hand-marks) produces ~60–100 figures across all themes with `< 10%` of figures bearing `warnings` non-empty.
2. `build_pools.py` produces three pool files; `paired.json` has the same id set as `pulse.json` and `step.json` (one-to-one).
3. `audition.py MTD####_fN` produces a `.mid` whose playback matches the figure's source-bar-position in the original MTD MIDI within audible tolerance.
4. `RealMotifSlotFiller` wired into a Pattern audition produces output that Matt judges audibly more musical than the same Pattern filled by RFB.
5. Per-figure encoding round-trips: a Figure extracted from MTD0389 figure 0, when played back at the original anchor pitch in C major, reproduces the original MTD notes (modulo articulation).

## Out of scope (Phase 1)

- **Auto-segmentation algorithm.** Designed in a separate spec once Phase 1 produces ground-truth data we can train/test against.
- **Modal scales beyond major / natural minor.** Harmonic minor, melodic minor, modes (Dorian, Mixolydian, etc.) deferred. Themes filtered to major/minor at curation.
- **Multi-time-signature handling.** Curation filters those out; extract.py refuses if it sees one.
- **Articulation extraction.** MTD-encoded staccato (short played duration) is dropped; `pulse` reflects IOI only. Articulation as a future Figure-level annotation is a separate concern.
- **Ornamentation extraction.** Trills, mordents, turns embedded in MIDI as 16th-note flurries are extracted as literal notes; recognizing them as ornaments is a future pass.
- **Cross-theme motif matching.** "These two figures from different themes share the same shape" — useful for pool de-duplication, deferred.
- **Audition with full DSP / instrument selection.** Phase 1 emits MIDI only; integration with `mforce_cli` rendering is a polish item if simple, otherwise deferred.
- **`RealMotifSlotFiller` chromatic resolution.** Whether the runtime chromatic offset lives on `MelodicFigure` directly or is resolved via Scale-level passing-tone walks is deferred until the slot-filler is actually wired up.
