## 1. Passage-level chord emission — the gap run 14 documented

Spec: `docs/superpowers/specs/2026-08-04-passage-chord-emission-design.md`

The template layer could not emit chords from a passage at all; harmony came
only from the section. That is why the `pedal_chords` prototype spells its
chords as three hand-voiced countermelody parts and bypasses the voicing tier
entirely — its own comment says so ("NOT role harmony: that role produced ZERO
events").

**Measured before designing anything, and it was worse than documented: the
harmony path was DEAD at HEAD.** All nine `test_jazz_turnaround_*` patches —
the entire voicing-selector A/B set from the chord-walker work — rendered
`peak=0 rms=0`, `Part 'chords': 0 events`, while the section timeline sat there
holding all 16 chords. Cause: `realize_chord_parts_` bails without a
`rhythmPattern`, and **no template in the repo has ever had one** — the Stage-11
migration off `chordConfig.defaultPattern` was never done anywhere.

One idea fixes both: an authored progression already carries durations, so it
should emit chords by itself, and a rhythmPattern RE-articulates it.

- `PassageTemplate.chordProgression` — passage-local harmony overriding the
  section timeline for that part. The section timeline is untouched, so melody
  chord-tone lookups still read it.
- `realize_chord_parts_` gets two modes through ONE voicing block: **span**
  (no rhythmPattern) = one event per authored chord at its own duration, now
  the default; **pattern** = the existing bar-strike behaviour.
- One shared progression parser for section + passage, accepting the flat
  authoring form and the canonical `{chords,pulses}` that `to_json` writes.
  That fixes a latent round-trip bug (to_json wrote canonical, from_json read
  only flat), and the flat form now carries `alteration` — without which bVI7,
  a German sixth, was not authorable at all.

Verified: 9/9 dead patches revived, 16 chords each, peak 0.68-0.91, voicing
selectors live (smooth picks inversions 2/1/2/3 across Dm7-G7-CM7-A7). Pattern
mode and melody-only templates byte-identical, wav and json. New
`patches/test_passage_chords_ger6.json` renders I-IV-ii-Ger6-I-V7-I over a
dominant pedal that releases a fifth to the tonic for the final chord;
`patches/test_passage_chords_precedence.json` proves precedence and
coexistence in one render (part with a passage progression gets its 7 chords,
part without gets the section's 1).

## 3. A template linter — `mforce_cli --lint-template`

The round-trip bug in front 1 is a class, not an incident: a key the loader
drops still renders, just not the piece that was authored. So, the comp
analogue of the dsp lane's patch linter — parse a template, serialize it
straight back, report what did not survive.

Findings are **classified**, because the first sweep reported 77 "dropped" and
most were noise: DROPPED (value is not a default), DEFAULTED (equals the type
default, which to_json omits by design), FORM (survives with a different
shape), CHANGED. Each DROPPED line carries the authored value — that is what
makes triage possible, since `shapeDirection = 1` and `cadenceTarget = -1`
ARE the defaults and no generic differ can know it. **Two rounds of fixing the
tool** to get there: an all-null connectors list accounted for 50 of the 77
until containers-of-defaults counted as defaults.

Sweep over 236 templates → 26 hard findings, 12 of them type-defaults. Real:

- **`chordConfig` was parsed but had no `to_json`** — a template that went
  through the engine came back with its chord octave/inversion/spread silently
  reset. Fixed.
- **`chordConfig.defaultPattern` in all 9 jazz patches** — Stage-11 leftover,
  read by nothing. Removed; render byte-identical after, which is the proof it
  was dead.
- **`sections[].keyName` in a run-13 probe template** — SectionTemplate has no
  such field, so three authored section keys did nothing. Backlogged (#13),
  not guessed at.

One anti-result recorded so nobody re-derives it: flat `voicingPriority` reads
as DROPPED and is NOT a bug — the parser lifts it into
`voicingProfile.priority` and to_json writes the nested form. Renamed, not
lost. And the FORM class (21 hits, all chordProgression array→object) is now
round-trip-safe: the same progression authored flat and canonical composes
byte-identically.

**A finding that fell out of the revival**, for backlog #8: with the patches
rendering again, the voicing-priority ladder collapses —
`test_jazz_turnaround_p05` and `_p1` are **byte-identical** renders, while
`_p0` differs. Priority is doing something at 0-vs-nonzero and nothing in
between. Not fixed blind; it is voicing-profile semantics (REVIEW 8).

## 4. The Bruckner pedal — backlog #6's last named item

Your run-12 note: *"Bruckner extreme = modulating over the pedal (needs key
fix)"*. It needed **two** key fixes, not the one stage 3 delivered. Stage 3
made MELODY key-aware; chord realization still resolved every ScaleChord
against the section scale, so a progression under keyContexts stayed put.

- Chords now resolve at their own beat via `Section::active_scale_at`. Strict
  no-op without keyContexts, verified byte-identical on both a chord-bearing
  and a melody-only control.
- `PassageTemplate.scaleOverride` — pins a passage's scale and opts it out of
  the section's key contexts. `Passage::scaleOverride` already did this at
  realize time; nothing could set it from a template.

The second fix was found by rendering, not by reading: with key-aware chords
the passage modulated correctly and the **pedal drifted 43-43-42-41**, because
key-awareness applied to it too and G is not in G-flat major. A pedal that
moves is not a pedal. Pinned, it holds 43 through all four key stations and
releases to 36 for the cadence.

`pedal_modulating` (+ `pedal_mod_minor3rds`): the same local progression
I-vi-IV-V re-lit in each key of a chromatic-third ring, over a stationary
dominant pedal, closing Ger6 → I(6/4) → V7 → I back home. The ring is chosen
so the held G *changes meaning without moving* — 5th of C, 3rd of Eb, alien to
Gb (the maximum-tension station). Verified in rendered chords:

    C-Am-F-G7 | D#-Cm-G#-A#7 | F#-D#m-B-C#7 | C-Am-F-G7 | G#7-C-G7-C

and the melody carries each key's signature (44 at the Eb station where C
gives 45). 4 renders in `renders/passage_bruckner/`.
