## 1. #7 — phrase-aware cadence placement

Spec: `docs/superpowers/specs/2026-08-10-phrase-aware-cadence-design.md`.

`AlternatingFigureStrategy` alternates two figure templates strictly per chord
and emits **one** Phrase, so a cadence lands on every other chord and
`pt.phrases[1..]` are unreachable — with them, `PhraseTemplate.cadenceType`,
`cadenceTarget`, `parallel` and `apply_cadence` itself. K467's opening is
2+2+4+4 bars and wants A-B / A-B / A-A-A-B / A-A-A-B. That is the standing AFS
impedance finding from 2026-04-13, and the oldest untouched comp item.

New `phrase_aware_figure` partitions the progression into one contiguous chord
span per `PhraseTemplate` (by beat budget where stated, else evenly, with every
phrase guaranteed at least one chord), alternates A/B on the position **within
the phrase**, and gives the last chord of each phrase a melodic cadence figure
driven by that phrase's own `cadenceType`. AFS is untouched and stays
registered — continuous alternation is a legitimate texture.

### The defect underneath, which is the real content

The strategy's first measurement was 4/4 arrivals correct **as composed** and
3/4 correct **as rendered**. The composer's running pitch cursor and the
realizer's were not the same pitch. Two independent reasons, both pre-existing
and both in the chord-tone walk AFS and the new strategy share:

* it applied a figure's **net** step in one hop, where
  `realize_phrase_to_events_` applies **every unit's** step in turn — and
  `pitch_walker.h` states in as many words that `step_chord_tone` is not linear
  over walks;
* it resolved the chord at the **running** octave, where realization resolves at
  `kBaseOctave`. Resolving at the running octave makes the candidate window
  follow the cursor, so a descending bias compounds instead of being
  re-anchored.

So a strategy computing a cadential approach was measuring from a pitch the
listener would never hear. The walk now mirrors realization exactly, in one
shared `chord_walk::advance`.

The second reason is also a crash. The deliberate norm-breaker arm (a 24-bar
phrase followed by an 8, 32 chords) died with `Unknown PitchDef offset: -3` —
the walk had descended past note number 0, where `Pitch::from_note_number` does
`n % 12` on a negative. **AFS crashes identically on the same progression**,
which is how I know it is pre-existing rather than mine; anchoring at
`kBaseOctave` bounds the walk and it renders.

`apply_cadence` gains an extracted `rebuild_cadential_tail` so a caller that
cannot use its degree accounting can supply the true starting degree. A
chord-driven phrase mixes `ChordFigure`s, whose steps are chord-tone indices,
not scale degrees — `apply_cadence` summing `net_step()` across them is exactly
the arithmetic that would go wrong.

### Measured

Same 12-chord K467-shaped progression, same seed, arrivals landing on the
declared cadence target degree (`renders/phrase_aware_ab/`,
`corpus/mtd_seg/phrase_aware_ab.py`):

```
alternating_figure    1/4
phrase_aware_figure   4/4
norm-breaker 24+8     crashed  ->  2/2
```

### Blast radius — stated as what it is

**This one is a static proof, not a measured null test**, because the dsp lane
went live and a revert-and-rebuild would have churned the shared build dir
under it. In AFS, `runningReader` is written by the walk and stepped, and
**never read by anything that reaches the output** — figures come from
`compose_figure`, which never sees it. So the walk change cannot move AFS
output. Corroborated dynamically: the AFS arm measured identically across all
three builds of this front. The 38 template hashes for that build are in
`renders/null_test_templates/after/` for a later run to diff against.

That dead accumulator is itself the reason AFS scores 1/4: nothing in AFS ever
consults the cursor it maintains.

## 2. #9 — the PAC held-note workaround

A Cadential phrase's arrival figure is forced to `FigureShape::HeldNote`.
That predates `apply_cadence` growing a real tail rebuild, and HeldNote defeats
it — one unit leaves `build_approach_steps` only its far branch.
`PhraseTemplate.cadentialArrival: "approach"` hands it a real figure instead.
**Default unchanged**; which one *resolves* better is taste, so it is REVIEW 18
rather than a blind default flip.

Two measurements, both against my own stated premise:

* **The leap I predicted does not happen.** Both arms enter the final note by
  +1 semitone, on both templates. The head already ends a step away, so the far
  branch never fires. Anti-result, recorded rather than left as folklore.
* **The held arm does not deliver the sustain it exists for.** Final-note
  duration 1.00 / 0.91 beats held, against 1.54 / 1.74 approach — the
  *approach* arm's arrival is the longer one, because `settle_tail` can absorb
  tail units into it and a single-unit figure has none to absorb.

### Six templates were rendering nothing

`DefaultPassageStrategy` opened with "should not happen — loader refuses
templates without startingPitch" and returned an **empty passage**. The loader
does not refuse them. Six of the 38 committed templates have no passage
`startingPitch` and have been emitting **zero events, silently**, for as long as
they have existed: `template_binary`, `template_mary`, all three
`template_ode_to_joy` variants, and `template_shaped_test` — which is how this
surfaced, it being one of only two templates with a cadential phrase.

A passage now inherits the first phrase that states a `startingPitch`, and
**refuses by name** when none does rather than emitting silence (run 18/19's
rule: refuse, do not substitute a placeholder). That left `template_binary`
correctly erroring — it has none anywhere — so it gets the piece tonic.

Not over-claimed: `template_ode_to_joy`'s figures are motif *references*, not a
literal transcription, so what it now renders is generated material, not the
tune the name suggests.

**Blast radius, measured exactly.** The baseline is the previous commit's own
build, so this is a true before/after: 38/38 renderable, **32 byte-identical, 6
changed**, and the 6 are precisely the 6 that were silent. Every change is
silence -> notes. The `cadentialArrival` knob contributes zero diffs, which is
shown rather than asserted.

New `corpus/mtd_seg/null_test_templates.py` does the render-and-hash sweep.
Runs 15 and 18 both did it by hand; it belongs in a script.

## 3. #8 — voicing open items

Two of the three land as `VoicingProfile` terms, both default-off. The third
does not, and that is the useful part.

* **`repeatPenalty`** (boring repeat). A repeated chord makes voice-leading
  distance 0 for the identical voicing, so it wins by a mile — the random
  selector only dodges this by accident. Consecutive identical voicings
  **1 -> 0** on `test_jazz_turnaround_smooth`, with top-voice span unchanged at
  3 semitones: it fixes the repeat without destabilising register.
* **`cadential`** (cadential chord role). Restricts an arrival to root
  position, *on top of* any allow-list rather than replacing it. Chords in root
  position **1/16 -> 15/16** with it set on every chord (in real use a profile
  selector sets it on the arrival alone). The 16th is unreachable; left as
  measured, not explained away.

### `registerPenalty` — two attempts, both worse than nothing

```
attempt 1  penalise the octave-search offset      drift  +1.5 -> +4.5 semitones
attempt 2  penalise mean pitch vs natural register top span   3 -> 14
           (weight 0.5 -> 2.0 changed nothing: the term saturates)
```

Attempt 1 failed for a reason worth keeping: pinning `dOct` removes the only
downward compensation the selector has, while **spread** — which is what
actually lifts the upper voices — stays unpriced.

But the finding upstream of both is that **the symptom does not reproduce at
HEAD**. On the very patch the 2026-04-20 observation was made on, the base
arm's top voice drifts **0 semitones over 16 chords, span 3**, and the bass span
is 3. These voicings are near-static, not climbing. Something in between — most
likely the run-15 harmony-path revival, which is when these patches started
rendering chords at all again — changed the behaviour that was described.

Two attempts, so it goes back on the backlog annotated, per the rule. **No dead
knob is left behind**: field, JSON and scoring term are all removed rather than
shipped defaulted-off, because a knob whose only measured effect is negative is
a trap. `voicing_profile.h` carries the note so nobody re-derives it.

Null test for this front: **38/38 byte-identical** against the previous
commit's build.
