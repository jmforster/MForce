## REVIEW 17 — passage endings off/beat/bar (passage_end_grid)

Run 18's three arms were produced by a one-off driver that was never kept.
Now it is: **corpus/mtd_seg/passage_end_grid_ab.py** rebuilds the same 21
jobs from engine_passage_strategies (5 strategies × 3 takes at seed
7311+1000k, 6 outliers at 7388), injects `endGrid` per arm (0 / 1.0 / 4.0)
into every passage, renders, and prints the ending-grid table.

One measurement bug caught in my own script before it could mislead: end
time as the max over ALL parts lets a 4-beat-unit pedal (always
barline-aligned) mask an off-grid melody ending — the off arm read 13/21.
Measured on the melody part, run 18 reproduces **exactly**:

| arm | on integer beat | on 4/4 barline |
|---|---|---|
| off | 6/21 | 5/21 |
| beat | 21/21 | 8/21 |
| bar | 21/21 | 21/21 |

— down to the individual off-grid end times run 18 quoted (9.375, 37.250,
50.750). The script keeps the melody-part measure with a comment saying why.
