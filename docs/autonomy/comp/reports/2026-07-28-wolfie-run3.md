## Front 2 — range-runaway guard [metric] ✓

Scoring surfaced a failure mode: **3 of 16 phrases blew past corpus range
[7,19]** — p02 ABAB = 52 semitones, p04 AAAB = 40, p13 AABB = 35. Root
cause is structural: "different-motif" seams and climb/sequence placement
use leadStep 0 (running pitch), so each figure's net_step accumulates
unbounded across 3–4 figures. A 4-octave span in a 5-second phrase is a
hard computer-music tell.

Fix (markov_phrase.py): `predicted_range()` (engine-free, reuses the
contour predictor) + rejection sampling in the batch driver. `--range-cap`
(default 19 = corpus range_p90) rejects a rolled combination whose
predicted span exceeds the cap and re-rolls up to `--max-tries` (24),
keeping the narrowest candidate if none fit.

Verified:

| batch (seed 1234, n=16) | mean composite | range > 19 |
|---|---|---|
| unguarded | 0.636 | **3** |
| guarded | 0.635 | **0** |

Strict improvement: eliminates the runaway failure mode at zero aggregate
cost. 3 of the 16 guarded phrases logged `tries=2`, independently
corroborating the ~19% raw-runaway rate. The composite barely moves because
the range screen is only 1/5 of the weight and only drops 1.0→0.5 out of
band — so the guard's perceptual value is larger than the metric delta.

## Front 3 — deliberate outliers + a scorer blind spot [metric] ✓

Per WORKFLOW's outlier directive, added `--pattern-set outlier`
(OUTLIER_PATTERNS: over-long repeats AAAAAAB / ABABABAB / AAA'A'B, guard
off by default) → renders/markov_phrases/outliers/. Six rendered (seed 77,
7–8 figures, 20–32 notes, ranges to 37).

Scoring them, over-repetitive phrases scored *high* (p04 AAAAAB rep_LxCount
25 → 0.741; p02 AAAAAAB rep 22 → 0.717); only the leap/range-heavy p03
ABABABAB (big_leap 0.258, range 33) got caught → 0.517.

My first read was "rep screen is a one-sided floor — bug." I checked it
against the corpus before changing anything, and **the data killed that
fix**: corpus repetition-coverage (rep_LxCount / n_notes) runs p50=0.59,
**p90=0.86, p95=0.92, max=0.97**, and rep_LxCount p95=21 / max=44. The
corpus is genuinely that repetitive (folk/theme material). p04's coverage
0.86 is only corpus-p90; p00's rep 16 is *below* corpus p90 — its 0.837 is
legitimate. A naive ceiling would punish corpus-faithful themes. So I did
**not** touch the scorer.

The honest gap: first-order interval/contour/rep distributions can't see
whole-phrase **monotony** (one figure hammered N×) — it needs a
higher-order self-similarity / motif-diversity screen, which is real work,
not a threshold tweak. Backlog #9 reframed accordingly; feeds REVIEW item 2.
(Separately logged the pre-existing `--csv` arg-parse quirk.)

Also noted (minor, pre-existing): score_generated.py's `--csv` arg-parse
treats the csv path as an input melody (harmless stderr warning; csv still
writes correctly). Logged for the scorer pass.
