## 1. Summary

Every wave evolution was two classes. The algorithm (`PluckEvolution` and its eleven siblings, each a `WaveEvolution` with `adjust`, `shape_excitation` and `evolve`) had no pins and no descriptors, so to be wired in a patch it was wrapped in a second class (`PluckEvolutionSource`: a `Component` and an `IEvolutionHolder`) whose only job was to hold the algorithm and show its settings as a node — handing them down as `const Setting<float>&` members in ten cases, rebuilding the algorithm object on every setting change in two (Pluck, Averaging), and hand-writing `prepare`/`start` for the four with pins. The wavetable held `Slot<IEvolutionHolder>`, cached a raw pointer to the evolution the holder carried, refreshed it on the slot hook and at prepare, and also owned an evolution of its own for the loader's string form — `"evolution": "pluck"` (or `"averaging"`, `"target"`) on the wavetable node with the evolution's settings and an `evolutionSeed` beside it, built by a forty-five-line branch in `patch_loader.cpp` that was the only way to reach `TargetEvolution`; to let that branch read its string, `wire_params_generic` skipped every string it met in a pin position, silently. Part 3 section 5 said what to do: each evolution a `Component` that implements the interface directly, settings declared once as Part 2's members and read where they are used, `IEvolutionHolder` and the cast deleted, `Slot<WaveEvolution>` on the wavetable, the string-typed path deleted, `TargetEvolution` registered — thirteen classes replacing twenty-six.

Now `WaveEvolution` is the family's abstract base, `struct WaveEvolution : Component`, and owns the lifecycle its members share: `prepare(ctx, maxLen)` prepares every pin then calls the `on_prepare(ctx, maxLen)` hook, `start(frames)` starts every pin — both non-virtual, the template-method shape Part 2 gave `ValueSource`, one level down. Its work verbs are `adjust(frequency)` once per note at the first sample (now `void`: every caller discarded the float), `shape_excitation(values)` once per note after the fill, `evolve(values, index)` once per sample. Thirteen evolutions derive from it — the twelve and `TargetEvolution` — each declaring its settings and pins as members (`Setting<float> muting{this, "muting", 0.0f, 0.0f, 1.0f}`), reading them where the old wrapper's references were read, and seeding its `Randomizer` once at construction from the registered or given seed; no setting change rebuilds anything. The four with pins (Reed, Bowed, Brass, BitRotate) keep them Manual, declared in the wrappers' order and advanced inside `evolve` in the old order; the base prepares and starts them. `WavetableSource` holds `Slot<WaveEvolution> evolution`, reads it per sample through `evolution.get()`, and has lost the cached pointer, `refresh_evolution`, the `on_slot_changed` override, `set_evolution` and `ownedEvolution_`. `TargetEvolution` is registered (Wavetable, Experimental, the derived label "Target Evolution") with `targetPartials` (an `Array`, default one row of 1.0), `targetLength`, `morphRate`, `holdCycles` and `decayFactor`, its period synthesised at prepare by the loader's arithmetic moved verbatim. The loader's `WavetableSource` branch is gone (the generic path builds it); a string in a Param, Input or Slot position fails the load naming the node, the pin and the string, and for `evolution` the tool that rewrites the old form: `tools/string_evolution_to_node.py` (eleven unit tests under ctest `tool_tests`). `kBranchKeys` lost the twelve keys the deleted branch alone read (142 → 130). The two live string-form patches are converted — `patches/baselines/delay_test.json` (tracked; its null-gate hash unchanged) and `patches/pending/harsh_pluck.json` (Matt's sandbox, under the signed target's 2026-10-05 line naming it; the original kept at `renders/scratch/ab34/harsh_pluck_before.json`) — and the eight archived ones in `patches/old/baselines_culled_2026-09-14/` (`ks_bowed_test`, `ks_breathy_test`, `ks_metallic_test`, `ks_morph_flute_test`, `ks_morph_horn_test`, `ks_morph_saw_test`, `pluck_muted_test`, `pluck_test`) are left as they are, never deleted, and fail the load naming the converter if ever opened. Six baselines (`algev_test_*`) carried a dead `evolutionSeed` on their node-form wavetable, a key only the deleted branch ever read; they lose it (the converter drops a stray one) and render as before.

One shape departs from the signed sentence, with its reason in the Ledger (ruling 1): the base rather than a pure interface beside `Component` (the 3.1 pattern of `IPartials` and `IFormant`). A pure interface would have kept four hand copies of the pin lifecycle and the forgotten-override class the 3.1 refuter named; the base writes the lifecycle once, and `Slot<WaveEvolution>`'s type-check works on either.

**Behaviour.** No render moved: the null gate is 78/78 after each of the three task commits — the twelve evolution patches in scope and `delay_test` across its conversion — the A/B over the 132 patches of `patches/library` and `patches/baselines` against the pre-checkpoint binary is 0 DIFFER, and a synthetic set of seven (`renders/scratch/ab34/synth.txt`) is 7 identical at the seal: Brass and EKS nodes from 3.3's set, an Averaging node with a non-default seed and every setting non-default (Review Focus 1), the pending patch unscored and scored, and two patches written in the STRING form, rendered by the old binary, converted in place by the tool and rendered by the new one — `pluck_string` (muting 0.35, seed 7) and `target_evolution` (the twenty partials of `ks_morph_saw_test`) — byte-identical across the conversion, which is the proof that the node form is the string form's arithmetic. No sample arithmetic changed: every changed line in `wave_evolution.h` that carries arithmetic is a wrapper reference become the evolution's own member, a deleted `return 0.0f`, a hook moved, Pluck's two deleted `freqAdj_` lines (a value no caller read, ruling 2), or Target's resample moved into `resample_target` behind the empty-target guard with `|| target_.empty()` on the hold test (operations unchanged, ruling 7) — section 6, table 2. Two things differ, neither a render: in the editor a Pluck or Averaging setting edited mid-stream no longer restarts the draw stream (the old wrapper rebuilt its evolution on every change — Pluck's with a constant seed that ignored the registered one, a latent bug the merge retires; a live `reanchor()` in a hook would restore the restart if ever wanted — the refuter showed the bug's reach: the pre-checkpoint binary renders the converted `pluck_string.json`, a node-form Pluck with `seed` 7, with a different hash from its own string-form render, because the old node form threw the seed away, and the new binary renders the string form's hash; tree-wide the only node-form Pluck nodes with a `seed` key are the two the converter wrote, so no pre-existing node-form render moves); and a string-typed evolution is refused rather than carried (the editor's `jsonExtras` carried the string through a save, and the engine now refuses that patch at play — only the eight archived patches have one). `targetWave`, the string form's explicit-period alternative, is not carried: no patch in the tree ever used it.

## 6. Decisions and rejected alternatives

The plan's sixteen rulings, then the execution rulings; the Ledger carries each with its reason.

1. **`WaveEvolution` is the family's abstract base, not a pure interface beside `Component`.** It derives from `Component` and owns the pin lifecycle once — `prepare(ctx, maxLen)` and `start(frames)` forward to every pin, non-virtual, `on_prepare` the hook — the template-method shape Part 2 gave `ValueSource`. Alternative: the 3.1 sibling pattern (`struct PluckEvolution final : Component, WaveEvolution` with `WaveEvolution` pure). Rejected: four hand copies of the pin lifecycle and the forgotten-override class the 3.1 refuter named (a holder that forgets its `prepare` never learns the rate, no compile error). `IPartials` and `IFormant` keep their shape; whether they take the same base is a CLEANUP row for 3.8.
2. **`adjust(frequency)` returns `void`.** Every caller discarded the float; Pluck's `freqAdj_` was the pitch correction the tuning allpass replaced (EKS's own comment said so) and reached no sample.
3. **Settings are read live; the draw stream is seeded once.** The old Pluck wrapper rebuilt its evolution on every setting change with a constant seed (`seed_` never received the constructor's), the Averaging wrapper with the right one; both restarted the stream on a live edit. The evolutions seed at construction and no setting change touches the rng. ## 10. C++ lessons

### Lesson 1: an abstract base that is also the interface, versus a pure interface beside it

C# has two words for this and makes you pick: an `interface` (no state, no bodies, as many as you like per class) or an `abstract class` (state, bodies, one per class). C++ has one word — a class — and the two shapes are just two ways of writing it: a class with only pure virtual functions and no data is what C# calls an interface, and `IPartials`, `IFormant` and the old `WaveEvolution` were exactly that. 3.1 chose that shape for the parts and wrote each one as `struct X final : Component, IPartials` — the C# `class X : Component, IPartials`, multiple inheritance of one base and one interface. This checkpoint chose the other shape for the evolutions: `struct WaveEvolution : Component` is an abstract class *with* two concrete methods, and each evolution derives from it alone. What was bought: the pin lifecycle is written once, in the base, over `pins()` — the registry `Component` already keeps — and a new evolution cannot forget it, because there is nothing to remember. What was given up: the freedom to be a `WaveEvolution` and something else at once, which nothing needs. The rule the choice follows is the one Part 2 followed for `ValueSource`: when every implementer of an interface would write the same two lines, those lines belong in a base, and the interface becomes an abstract class — the template method, with `on_prepare` the hook where a member says what is its own. `Slot<WaveEvolution>` does not care which shape it is: `dynamic_cast<WaveEvolution*>` works on an abstract base exactly as on a pure interface.

### Lesson 2: a member that files itself, versus a reference to someone else's member

The old evolutions held `const Setting<float>& muting;` — a reference to a setting that lived in the wrapper. A reference member is the C++ way of saying "I read this, I do not own it, and it must outlive me", and it has three consequences the wrapper paid for: the class cannot be assigned (a reference cannot be re-seated, so `evo_ = PluckEvolution(...)` was only possible because Pluck had no reference members — Averaging and Pluck baked copies instead, which is why they had to be rebuilt on every change); the referent's lifetime is the evolution's problem (fine inside one wrapper object, a trap the moment anyone copies the evolution out); and the thing being read is declared twice, once as the setting and once as the reference to it. The new evolutions own their settings: `Setting<float> muting{this, "muting", 0.0f, 0.0f, 1.0f};` is a member that registers itself with `this` as it is constructed (2.1's lesson 1), so the declaration, the storage, the descriptor and the read are one line and one object. The "rebuild" disappears not because it was optimised away but because there is nothing left to copy. A C# reader has met the same shape as the difference between a field and a captured variable in a closure: the closure reads someone else's storage and dies with it; the field is yours.

### Lesson 3: a return value nobody reads

`float adjust(float frequency)` returned a pitch correction for the whole life of the C++ port, and every caller wrote `evolution_->adjust(currFreq_);` and threw it away. Pluck computed `freqAdj_` from a logarithm each note and returned it; eleven others returned `0.0f`. The compiler cannot see that a non-`void` return is a lie: a discarded return is legal C++ (and legal C#), so the signature kept promising something the tuning allpass had taken over long ago. Two tools make the compiler care: `[[nodiscard]]` on the function, which turns a discarded call into a warning (and, under warnings-as-errors, a refusal), and the honest signature, `void`, once no caller reads it. This checkpoint chose the second, because the first would have made twelve callers write `(void)` around a value they do not want. The general rule: a return type is part of the contract, and a contract nobody enforces drifts; when you find one, ask whether to enforce it or delete it, never leave it.

### Lesson 4: idempotence as a contract you can lean on

Reed's and Brass's wrappers prepared `breath` before `reedStiffness`; the base now prepares pins in declaration order, the other way round. No byte moved, and the reason is a contract written on `ValueSource::prepare`: "Calling it twice with the same context changes nothing a render can see." Idempotence — doing a thing twice is the same as doing it once — is what makes order between independent calls irrelevant: if each pin's prepare leaves its source in the one state prepare leaves it in, two pins prepared in either order leave two sources in those states. `start` is weaker (it resets per-note state, so it is idempotent per note but not across notes), and the argument for it needed one more step: two distinct sources started in either order are independent, and a source reachable from both is started twice in either order. C# has the same idea in `IDisposable.Dispose` ("safe to call more than once") — a documented contract, not something the language checks — and the way to keep such a contract honest is the way 2.2 and this checkpoint did it: a test that calls prepare twice and asserts the count (`ctxPrepares == 2`) and the render. A contract with a test is a thing you can lean on; one without is a hope.
