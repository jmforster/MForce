## Front 2 — SlewLimiterSource (item 3g) ✓

New `SlewLimiterSource`, category Filter, modes Slew / Lag / Peak, with
`rate` and `fallRate` as ValueSources (so both are envelope-able) and a UI
menu entry under Filters. Spec:
`docs/superpowers/specs/2026-08-05-slew-limiter-design.md`.

**The backlog's premise was wrong and measuring caught it.** The item assumed
the clicks are STEPS. They are one-sample IMPULSES: the velvet source goes 0,
±0.5, 0. A sign-keyed rate limiter turns that into a one-sample impulse of
height `rate*dt` — it makes the click quieter, not longer. Rendering a rate
ladder on the naive insertion would have measured a level drop and nothing
else. `Peak` mode is magnitude-keyed instead (attack toward the input while
`|in| > |held|`, otherwise decay toward zero at `fallRate`), so an impulse
becomes a jump plus a glide back to rest, symmetric in both polarities.

`tools/verify_slew.py` against `patches/slew_test/` — ALL PASS:

| case | measured | predicted | note |
|---|---|---|---|
| Slew rate 200 | 10.046 ms | 10.000 ms | nonlinearity 0.002% (a straight ramp) |
| Slew rate 2000 | 1.019 ms | 1.000 ms | nonlinearity 0.003% |
| Lag rate 200 | tau 5.002 ms | 5.000 ms | nonlinearity 33% (correctly NOT straight) |
| fallRate asymmetry | 10.05x | 10x | |
| Peak on impulses | 10.00 ms both polarities | 10.00 ms | |
| Slew on impulses | +10.00 ms / −0.02 ms | — | the asymmetry Peak exists to fix |

That last row is the evidence for the design change rather than my say-so:
sign-keyed Slew holds a positive impulse for 10 ms and a negative one for a
single sample.

## Front 2b — the click ladder (REVIEW 15)

`tools/gen_slew_clicks.py` inserts the limiter (Peak) between the velvet
phase source and FMSource in the run-20 PoC, at a `fallRate` ladder.

The dial is not a plain lowpass and it is worth saying what it actually is:
the impulse jumps phase 0.5 cycles and glides back over `0.5/fallRate`
seconds, and a linear phase glide IS a constant frequency offset — so during
the glide the carrier is detuned by `fallRate/2` Hz. Bigger `fallRate` = a
SHORTER but more frequency-deviant chirp. Duration trades against deviation.

Measured over the 0.25 s attack window (`tools/measure_slew_clicks.py`):

| render | attack centroid | >8 kHz | vs control |
|---|---|---|---|
| control (raw steps) | 7116 Hz | 37.92% | 1.000x |
| fallRate 20000 | 7116 Hz | 37.92% | 1.000x |
| fallRate 5000 | 6404 Hz | 33.76% | 0.900x |
| fallRate 1000 | 4745 Hz | 21.42% | 0.667x |
| fallRate 200 | 3667 Hz | 15.76% | 0.515x |
| fallRate 50 | 3237 Hz | 13.61% | 0.455x |

Monotonic, 6 of 6 distinct by sha256. fallRate 20000 landing exactly on the
control is the expected degenerate end (a 0.025 ms glide is about one sample)
and doubles as the ladder's own control.

## Front 3 — broadband_ratios empty-band guard (item 3e-NEXT a) ✓

`BANDS[0]` is (160, 700) Hz. Any eval note above 700 Hz leaves it with no
harmonic line, and the ratio was `between_e / 1e-12` — a noise-floor
measurement inflated by twelve decades.

**Live in the stored piano reference, not hypothetical**: C6 band0 =
**4.63e+11**, against O(1) or smaller for every other note. C6 (1046.5 Hz)
was the only eval note above 700 Hz, so the run-20 piano smoke's term3 was
dominated by that one cell.

Empty bands now return NaN; `score_candidate` nanmeans over them (a missing
band is missing, not agreement) and skips a note whose every band is empty.
`research/ml_ears/test_broadband_guard.py` keeps the pre-fix formula inline
so the blowup is SHOWN (1.325e13 at f0 = 880 Hz) and checks populated bands
come back bit-identical. ALL PASS. Regenerating `out/piano_reference.json`
changes C6 band0 to nan and leaves every other value identical to the digit.

**A finding that enlarges item (b):** piano band2 ratios run 120 (C3), 260
(C5), 2056 (G4). Both the heterodyne and the line mask sit at `k*f0` and
ignore inharmonicity, so high partials — stretched by `sqrt(1+B n^2)` —
fall off the mask and get counted as inter-harmonic energy. (b) therefore
affects `broadband_ratios` as well as `harmonic_env`/`motion`, which is a
larger blast radius than the item currently states.
