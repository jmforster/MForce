## Front 2 — Additive performance profiling (item 8 stage 1, G4) [metric] ✓

Added a stderr render timer to the CLI `run_patch` path (`render=…ms … Msamp/s
… x realtime`) — permanent, drives all future perf work. Profiler
tools/prof_additive.py sweeps minimal AdditiveSource+FullPartials patches
identical but for partial count (8..200), min-of-5 timed.

Baseline (graph-path live synthesis, 4-core box, min-timed):

    partial cost ~= 65-90 ns per sample per partial (marginal fit 64 ns).
    linear in partial count (Msamp/s halves as N doubles).
    => single voice saturates one core at ~325 partials real-time @48kHz.

Hot path: `Partials::get_partial_value` (partials.h:476) — per partial per
sample: one `std::sin` (always) + `std::fmod` phase wrap + guarded
transcendentals (`std::pow` rolloff when ro!=0; `exp2` motion; `sqrt` bandwidth
— all off in the baseline). The scalar `std::sin`/`fmod` are the floor.

Investigation note — an apparent 25x "fast path" (viola-style patches timing
~10 ms where graph patches took ~150 ms) was chased down and is a MEASUREMENT
artifact, not a real speedup: patches with `instrument`+`score` blocks
pre-render their note buffers at load time (instrument architecture), so
`run_patch`'s timer — which wraps only `mixer->render()` — measures buffer
*mixing*, not synthesis. Graph-only patches drive live synthesis through the
timer, so the sweep above is the correct steady-state figure. Consequence for
stage 2: to profile instrument-path synthesis, the timer must move to (or be
added at) the pre-render, not the mixer.

No cheap win found (the rolloff-`pow` and viola leads both dissolved under
clean measurement). Stage 2 is genuine engineering — SIMD the per-partial
loop and/or iFFT overlap-add — and iFFT-OLA is not bit-identical, so it will
need Matt's ear. Filed as item 8 stage 2. Not attempted blind.
